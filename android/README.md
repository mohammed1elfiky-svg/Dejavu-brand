# تطبيقات Dejavu لأندرويد

مشروع Gradle واحد متعدد الوحدات. التطبيق الحالي: **تطبيق العملاء** (`app-customer`).
تطبيق الإدارة سيُضاف في المرحلة 4 ويستخدم نفس الوحدات المشتركة.

```
android/
├── core/model      نماذج بيانات الـ API (Kotlin خالص)
├── core/network    عميل Retrofit + التوكن (تجديد تلقائي مرة واحدة عند 401) + تغيير الخادم أثناء التشغيل
├── core/data       المستودعات (الجلسة، الكتالوج، السلة، العناوين، الطلبات، المرتجعات) + ترجمة رسائل الخادم
└── app-customer    واجهة Jetpack Compose (عربي، من اليمين لليسار)
```

## التقنيات

Kotlin 2.2 · Jetpack Compose (Material 3) · Navigation Compose · ViewModel + StateFlow ·
Retrofit + OkHttp + kotlinx.serialization · Coil 3 · Android Keystore لتشفير التوكن · minSdk 26 / targetSdk 36.

الاعتماديات تُربط يدوياً في `AppContainer` (عددها صغير ولا يحتاج إطار DI). يمكن الانتقال إلى Hilt لاحقاً عند نمو التطبيق.

## الشاشات

| الشاشة | ما تفعله |
|---|---|
| الرئيسية | بحث، الأقسام، مختارات Dejavu، وصل حديثاً |
| الأقسام / المنتجات | شجرة الأقسام، شبكة منتجات بالبحث والترتيب والتحميل التدريجي |
| المنتج | معرض صور، اختيار اللون ثم المقاس، التوفر الفعلي، الكمية، أضف إلى السلة |
| السلة | تعديل الكميات، كود الخصم، مشاكل المخزون، تقدير الشحن لعنوانك الافتراضي |
| إتمام الطلب | اختيار/إضافة عنوان، طريقة الدفع، ملاحظات، ملخص، تأكيد |
| طلباتي | القائمة، التفاصيل مع خط زمني للحالة، تتبع الشحن، الإلغاء، طلب الإرجاع |
| حسابي | الملف، العناوين (اختيار المحافظة من مناطق التوصيل فقط)، طلبات الإرجاع، الخادم، الخروج |

**الدفع:** الدفع عند الاستلام، وإنستاباي/المحفظة/التحويل البنكي (يؤكدها الفريق يدوياً).
الدفع بالبطاقة ينتظر ربط بوابة الدفع (المرحلة 5).

## الحصول على التطبيق (APK)

كل رفع للكود يبني **APK تجريبي** تلقائياً على GitHub Actions:
1. افتح تبويب **Actions** في المستودع ← آخر تشغيل لـ **Android**.
2. انزل إلى **Artifacts** ← حمّل `dejavu-customer-debug-apk` (ملف zip بداخله الـ APK).
3. انقله للموبايل وثبّته (اسمح بالتثبيت من مصادر غير معروفة).

## ربط التطبيق بالخادم

من داخل التطبيق: **حسابي ← الخادم**، ثم اكتب الرابط واضغط "حفظ واختبار".

| أين يعمل الخادم | الرابط |
|---|---|
| على نفس الكمبيوتر مع محاكي أندرويد | `http://10.0.2.2:3000` (الافتراضي) |
| GitHub Codespaces | رابط المنفذ 3000 من تبويب PORTS، **بعد جعله Public** (زر يمين ← Port Visibility ← Public) |
| خادم على الإنترنت | `https://your-server.com` |

يمكن أيضاً تغيير الافتراضي وقت البناء: `./gradlew assembleDebug -Pdejavu.apiBaseUrl=https://your-server/api/v1/`

النسخة التجريبية (debug) تسمح بـ `http`. نسخة الإنتاج (release) تقبل `https` فقط.

## البناء محلياً

```bash
cd android
./gradlew :app-customer:assembleDebug          # يحتاج Android SDK (Android Studio يثبته تلقائياً)
./gradlew -PjvmOnly=true test                  # الوحدات المشتركة فقط، بدون Android SDK

# اختبارات العقد مع خادم يعمل ببيانات تجريبية:
DEJAVU_API_URL=http://localhost:3000/api/v1/ ./gradlew -PjvmOnly=true :core:data:test
```

أو افتح مجلد `android/` في Android Studio وشغّل `app-customer`.

## الاختبارات

- **وحدات:** تنسيق المبالغ، تجديد التوكن (مرة واحدة لعدة طلبات متزامنة)، إنهاء الجلسة، تحليل أخطاء الخادم،
  تغيير الخادم، التحقق من المدخلات، ترجمة الرسائل.
- **عقد مع الخادم الحقيقي:** رحلة العميل كاملة (تسجيل ← عنوان ← سلة + كوبون ← طلب ← إلغاء ← خروج)،
  وقراءة كل طلبات ومرتجعات العميل التجريبي. تعمل في CI ضد خادم ببيانات تجريبية، فأي اختلاف بين التطبيق والـ API يظهر فوراً.
